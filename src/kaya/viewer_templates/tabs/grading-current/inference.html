The data, not the priors, did the work — and here is the evidence for that claim

Every number on this page is a posterior mean: the average of the values a parameter took across the draws the sampler kept. That is only worth anything if two things hold. First, the posterior has to come from the data rather than from the prior — a parameter the data cannot see just reports its prior back at you. Second, the sampler that produced it has to have converged. Both are checkable, so both are checked here, for every parameter, rather than asserted.

A prior is what the model believed before seeing any data; the posterior is what it believes after. Defaults below are the v3_conf fit (the 29-gym net50 network, confident subset, 4 chains × 500 draws after 600 tuning iterations), but every fitted model version is selectable.

Prior in grey, posterior in blue, on a common horizontal scale per parameter (each parameter’s own units — see the Symbols panel). Where the blue is much narrower than the grey and sits somewhere the grey did not concentrate, the data did the work. Where the two overlap closely, the parameter is barely identified and the prior is carrying it. Click any parameter for its chains and full statistics.

Four chains started apart and agreed — per parameter, not on average

Pick a parameter to see its prior against its posterior, and what the four chains did while sampling it. A chain is one independent run of the sampler; four of them start from different random points, and if they all end up describing the same distribution, that is evidence the answer is a property of the model rather than of where the sampler happened to begin.

How to read a trace plot

Four chains start from different random points and wander around the posterior. Each line is one chain’s value for the parameter at each draw. What you are looking for is boring:

what you seewhat it means
Fuzzy caterpillar — dense, even, no pattern Good. The chain is bouncing around the same region draw after draw, which is what sampling a settled distribution looks like.
All four lines on top of each other Good. Chains that started in different places agree about where the answer is. This is what R̂ (R-hat) measures numerically.
Chains on visibly different levels (watch the dashed per-chain means) Bad. They disagree. The posterior mean is then an average over chains that never reconciled — this is R̂ above 1.01.
Slow drift or a trend across the plot Bad. Still moving, so it has not settled. Needs longer warm-up or a better parameterisation.
Flat stretches where a line sticks Bad. Proposals are being rejected repeatedly; the sampler is stuck against a difficult bit of geometry.
Wide excursions to far-off values Usually heavy tails, sometimes a second mode. Worth checking against the density plot beside it.

Where the warm-up went. PyMC discards tuning draws by default, so for the earlier fits the 600 warm-up iterations were thrown away before the trace was written and cannot be recovered. Fits run after this was noticed keep theirs, and show it shaded at the left with x = 0 marking the handover. Warm-up is where the dramatic convergence happens — chains starting far apart and pulling together — which is exactly why it is worth keeping.

The rank plot option asks the same question a different way, useful because good traces all look alike and the eye is bad at judging four overlapping squiggles. Pool every draw from every chain, sort them, and ask where each chain’s draws landed in that ordering. If the chains explored the same distribution, each contributes evenly across the whole range and its bars sit flat on the dashed line. A chain parked somewhere the others never went piles up at one end.

Most parameters land in the same place whichever height form is bolted on beside them

Each height form is a different model, but most parameters appear in all of them. Overlaying their posteriors answers something no single fit can: is this number a property of the data, or of the height form that happened to be fitted alongside it? Pick any parameter above to change this plot.

Twenty-two models have been fitted, which is far too many to overlay usefully. The selection below controls every multi-model figure in this section — this one, the fitted curves, and the corner plot. It defaults to the seven height forms of one version, since those are the models that are genuine alternatives to each other. The refits are the same model run again with a different random seed: they exist to measure how much the sampler wobbles, and overlaying them shows only that it does. The side experiments change something other than the height form, so their posteriors answer a different question.

The fitted height curves disagree about shape but agree the effect is small

The parameters trade off along narrow ridges, which is exactly why the sampler struggles

A corner plot shows every pair of parameters plotted against one another, using the same draws. Round blobs mean the parameters are being pinned down independently. Tilted, narrow ridges mean they are trading off — the data constrain their combination much better than either one alone, and the sampler has to crawl along that ridge instead of moving freely. That geometry is the cause of every convergence complaint further down this page, and it is visible here rather than merely asserted.

Overlaying every model asks the same question the posterior overlays above do, but in two dimensions: if two models draw the same tilted ridge, that ridge is a property of the data rather than of the height form fitted beside it. Contours read better than points once several models are stacked; points show the tails and any stragglers the contours smooth away. Everything (full width) puts every parameter in one plot across the whole pane.
