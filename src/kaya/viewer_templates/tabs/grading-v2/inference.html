Priors, Posteriors, and What the Sampler Did

Every number on this page is a posterior mean, which is only worth anything if the posterior came from the data rather than from the prior, and if the sampler that produced it actually converged. Both claims are checkable, so here they are, for every parameter, from the v3_conf fit (net50/confident, 4 chains × 500 draws after 600 tuning).

Prior in grey, posterior in blue, on a common horizontal scale per parameter. Where the blue is much narrower than the grey and sits somewhere the grey did not concentrate, the data did the work. How to read a trace plot

Four chains start from different random points and wander around the posterior. Each line is one chain’s value for the parameter at each draw. What you are looking for is boring:

what you seewhat it means
Fuzzy caterpillar — dense, even, no pattern Good. The chain is bouncing around the same region draw after draw, which is what sampling a settled distribution looks like.
All four lines on top of each other Good. Chains that started in different places agree about where the answer is. This is what R̂ measures numerically.
Chains on visibly different levels (watch the dashed per-chain means) Bad. They disagree. The posterior mean is then an average over chains that never reconciled — this is R̂ above 1.01.
Slow drift or a trend across the plot Bad. Still moving, so it has not settled. Needs longer warm-up or a better parameterisation.
Flat stretches where a line sticks Bad. Proposals are being rejected repeatedly; the sampler is stuck against a difficult bit of geometry.
Wide excursions to far-off values Usually heavy tails, sometimes a second mode. Worth checking against the density plot beside it.

Where the warm-up went. PyMC discards tuning draws by default, so for the earlier fits the 600 warm-up iterations were thrown away before the trace was written and cannot be recovered. Fits run after this was noticed keep theirs, and show it shaded at the left with x = 0 marking the handover. Warm-up is where the dramatic convergence happens — chains starting far apart and pulling together — which is exactly why it is worth keeping.

The rank plot option asks the same question a different way, useful because good traces all look alike and the eye is bad at judging four overlapping squiggles. Pool every draw from every chain, sort them, and ask where each chain’s draws landed in that ordering. If the chains explored the same distribution, each contributes evenly across the whole range and its bars sit flat on the dashed line. A chain parked somewhere the others never went piles up at one end. Strictly a diagnostic — ignore it if the trace tells you what you need.

How the parameters trade off against each other

A corner plot shows every pair of parameters plotted against one another, using the same draws. Round blobs mean the parameters are being pinned down independently. Tilted, narrow ridges mean they are trading off — the data constrain their combination much better than either one alone, and the sampler has to crawl along that ridge instead of moving freely. That is the geometry behind every convergence complaint on this page.

Overlaying every model answers the same question the posterior overlays above do, but in two dimensions: if two models draw the same tilted ridge, that ridge is a property of the data rather than of the height form bolted on beside it. Contours read far better than points once several models are stacked; points show the tails and any stragglers the contours smooth away. Everything (full width) puts every parameter in one plot across the whole pane.
